## R1 — Recover a prepared transaction whose stage was never created

**Severity: P2 / Medium. Original finding: H03, incompletely closed.**

Locations: `analysis/utils/merge_wf16s_cohort.R:325–329` and `:921–932`.

The merger persists its `prepared` journal before attempting `dir.create(stage_dir)`. If this is a new destination and stage creation fails—or the process dies between those operations—the destination, stage, and backup are all absent, but the journal remains. Recovery handles a prepared transaction only when `stage_exists` is true. The absent-stage state therefore falls through to `E_COHORT_RECOVERY_REQUIRED: ambiguous publication state`.

This turns a transient creation failure or an interruption before any bundle was written into a persistent failure for that destination. Subsequent normal invocations cannot recover and retry, although there is no prior bundle or transaction material requiring preservation. A crash after deleting an incomplete new stage but before deleting its journal can reach the same state.

### Evidence

`output/re-audit-20261011/probes.R` creates two valid synthetic producer bundles and wraps only the merge function's `dir.create` binding to return false for the transaction stage. It then retries with the unmodified merger:

```text
STAGE_CREATE_FAILURE: E_COHORT_STAGE_FAILED: could not create transaction stage ...
RETRY: E_COHORT_RECOVERY_REQUIRED: ambiguous publication state ...
JOURNAL_REMAINS: TRUE
```

The log is `output/re-audit-20261011/probes.log`. This reproduces an ordinary failed operation at the journal/stage boundary without altering production code. Existing child-process crash tests begin at later publication hooks, after the stage exists, so they do not exercise this boundary.

### Recommendation

Add an explicit recovery transition for a validated `prepared` journal with `had_prior == FALSE` and no destination, stage, or backup. Check both file and directory existence; a regular file occupying a transaction path is not an absent path. Remove only the checked journal and allow a fresh attempt. Retain the fail-closed behavior when any unexpected occupant or recovery material exists.

```diff
 # After journal identity/schema/path validation:
+if (phase == 'prepared' && !had_prior &&
+    absent(destination) && absent(stage) && absent(backup)) {
+  remove_cohort_journal_checked(journal_path)
+  return(invisible(TRUE))
+}
 # Existing branches continue to validate and preserve occupied paths.
```

### Acceptance criteria

- Stage-creation failure leaves no permanent blocker: after the underlying failure is removed, the same merge command succeeds without manual journal deletion.
- A child terminated immediately after the first journal write, before stage creation, recovers on the next invocation.
- A child terminated after incomplete-stage cleanup but before journal removal also recovers.
- Unexpected regular files/directories at destination, stage, or backup prevent this transition and remain untouched.
- Existing old-bundle restoration and post-publication recovery tests continue to pass.

## R2 — Teach release verification the new rarefaction-unavailable contract

**Severity: P2 / Medium. Original finding: H09, module fix verified but end-to-end verification incomplete.**

Locations: `tests/verify_release_run.R:661–677`, `:680–696`; related producer changes in `analysis/02_alpha_diversity.R:233–271`.

The alpha module now correctly retains full-depth metrics and records per-sample `E_RAREFACTION_NUMERIC_DOMAIN` skips. However, the release verifier still unconditionally opens `rarefaction_resamples_long.tsv` whenever alpha is completed, requires all release samples to appear in it, and requires the full sample-count × iteration-count × metric-count number of rows. It also unconditionally reads `alpha_plot_registry.tsv`.

When all samples are outside the rarefaction domain, these resampling artifacts are intentionally not produced. When only some samples are outside the domain, the verifier's sample-set and row-count assertions still reject the valid subset. The new module test checks skip files and preserved Shannon metrics but never checks release-verifier acceptance.

### Evidence

A synthetic minimap2-derived input containing one species with 3,000,000,000 counts, four unclassified counts, and no assignments completed the real pipeline with `qc,alpha,composition,kreport`. Its manifest records a completed run, and `rarefaction_availability.tsv` records both expected numeric-domain skips.

The complete release verifier first stopped at its **pre-existing** unconditional assignment-QC reconciliation read, because assignments are optional for this run. That earlier limitation is not attributed to Luna's changes.

To isolate this finding, `output/re-audit-20261011/verify-alpha-branch.R` evaluates the **unchanged parsed alpha-verification branch** and its helper functions against the published run. It passes through the full-depth metric checks and then fails:

```text
cannot open file '.../02_Alpha_Diversity/rarefaction_resamples_long.tsv':
No such file or directory
```

Evidence: `large-run.log`, `large-run/run_manifest.json`, `large-run/02_Alpha_Diversity/rarefaction_availability.tsv`, and `alpha-verify.log`, all under `output/re-audit-20261011/`.

### Recommendation

Have the independent verifier derive rarefaction eligibility from the immutable input and the documented numeric limit, then verify the skip ledger against that expectation. Require long-table samples and row counts only for eligible samples. Verify appropriate absent/skip artifacts when none are eligible, and validate plot/phylogeny outputs according to whether resampling actually ran. Do not merely waive missing-file errors or trust the producer's skip claim without checking the counts.

```diff
+eligible <- independently_derive_rarefaction_eligibility(classified_counts)
+verify_availability_ledger(expected_ineligible_samples = samples[!eligible])
-long <- read.delim(resample_path)
-assert(setequal(long$SampleID, release_samples))
+if (any(eligible)) {
+  long <- read.delim(resample_path)
+  assert(setequal(long$SampleID, release_samples[eligible]))
+  assert(nrow(long) == sum(eligible) * iterations * metric_count)
+  verify_resampling_plots_and_registry(...)
+} else {
+  assert_expected_rarefaction_skip_artifacts(...)
+  assert_absent_resampling_artifacts(...)
+}
 # Continue verifying full-depth metrics for every sample.
```

### Acceptance criteria

- Independently verify ordinary, all-ineligible, and mixed eligible/ineligible alpha outputs.
- Cover both phylogenetic-enabled and phylogenetic-disabled cases.
- Missing outputs for an eligible sample still fail; unjustified skip records and missing skip records fail.
- Valid full-depth metrics remain mandatory for every sample.
- Add a test reaching the actual release-verification alpha branch, not only `run_alpha()`.
