## H01 — Preserve the permutation design instead of filtering label-preserving permutations

**P1 / High.** Locations: `analysis/03_beta_diversity.R:305–309`, `:315–357`; tests in `tests/testthat/test-cohort.R`.

After `permute::shuffleSet`, the implementation removes every permutation for which group labels are unchanged. Those permutations are legitimate members of the exchangeability design. Removing them conditions the null distribution on a label change. The resulting matrix is passed to both `adonis2` and `permutest.betadisper`.

**Reproduction.** With `g = factor(c('A','A','B','B'))`, `d = dist(matrix(c(0,1,10,11), ncol=1))`, and all 23 nonidentity permutations, `adonis2(d ~ g)` returns **p = 0.3333333**. The repository's filter retains 20 rows and returns **p = 0.2380952**, with the same observed F = 200. This isolates the defect independently of distance construction. It demonstrates downward distortion in this example; it does not imply a constant correction factor for other datasets.

The official [permute shuffleSet documentation](https://gavinsimpson.github.io/permute/reference/shuffleSet.html) describes sampling/enumerating the specified permutation design, and [vegan's permutation documentation](https://vegandevs.github.io/vegan/reference/permutations.html) describes consuming supplied permutation matrices. Neither supplies a justification for this post hoc label-based exclusion.

**Recommendation.** Preserve the design's permutation matrix. Determine whether group labels can change as an estimability diagnostic, independently of the permutation sample. A sampled matrix with no label changes is not by itself proof that the design forbids changes. Retain block restrictions and explicitly distinguish a nonexchangeable design from insufficient sampled permutations. Reassess previously reported PERMANOVA and dispersion p-values produced by this branch.

```diff
 permutation_matrix <- permute::shuffleSet(nrow(meta), nset=n_perm, control=control)
-permutation_matrix <- permutation_matrix[label_changing, , drop=FALSE]
-if (!nrow(permutation_matrix)) can_run_permanova <- FALSE
+design_status <- assess_group_exchangeability(meta$Group, control)
+if (!design_status$testable) record_design_skip(design_status$reason)
+# Pass the unfiltered admissible matrix to the supported tests.
+# Report actual row count; do not call it 'admissible_label_changing'.
```

**Verification criteria.** Exhaustive four-sample oracle returns p = 1/3; compare the pipeline result with direct vegan calls using the exact same matrix. Add unrestricted, mixed-group blocked, and wholly confounded blocked designs. Check betadisper independently. Retain seeded reproducibility and sample-order invariance. Tests must assert numerical p-values, not only output existence and column names.

## H02 — Protect the destination throughout cohort overwrite

**P1 / High.** Locations: `analysis/utils/merge_wf16s_cohort.R:263–275`, `:710–729`.

Ownership and existing-file hashes are checked near the start. Publication later rechecks source files only, moves whatever currently occupies the destination to a backup, publishes the stage, and recursively removes the backup. There is no destination lock or final destination snapshot check. A file added after the initial validation is therefore included in the backup and deleted. Concurrent mergers can also pass the same initial check.

**Reproduction.** Created a synthetic owned bundle, then ran overwrite with a function-local `file.rename` wrapper that inserted `late-user-note.txt` immediately before the destination-to-backup rename. Merge returned success; the new file was absent afterward (`LATE_FILE_RETAINED FALSE`). The wrapper models an external write at the publication boundary; production files were not modified. This demonstrates the consequence of the unchecked interval, not an observed concurrent production incident.

**Recommendation.** Acquire a canonical destination lock before inspecting existing output and retain it through cleanup. Snapshot the destination census and hashes, revalidate before the swap, and inspect the renamed backup before deletion. Locks serialize cooperating writers; they do not prevent manual edits. Abort or retain recovery material when the destination changes, and never delete an unexpected file.

```diff
+lock <- acquire_cohort_output_lock(canonical_destination)
+on.exit(release_output_lock(lock), add=TRUE)
+prior <- validate_and_snapshot_cohort_destination(destination, overwrite)
 ... build and validate stage ...
 assert_merge_sources()
+assert_destination_unchanged(destination, prior)
 rename(destination, backup)
+assert_backup_matches_snapshot(backup, prior) # retain on mismatch
 rename(stage, destination)
-unlink(backup, recursive=TRUE, force=TRUE)
+remove_verified_backup_or_retain_for_recovery(backup, prior)
```

**Verification criteria.** Two subprocesses targeting one destination cannot publish concurrently. Inject added, removed, and modified files at each publication boundary; unexpected data survives. A new destination created by another writer is never silently replaced. Test canonical path aliases on Windows and POSIX. Keep all fixtures under disposable temporary roots.

## H03 — Add durable recovery to cohort publication

**P2 / Medium.** Locations: `analysis/utils/merge_wf16s_cohort.R:610–618`, `:712–731`; compare main-run recovery in `analysis/utils/atomic_io.R`.

The merger has two directory renames but no durable journal. Termination after moving the old destination to backup leaves the public destination missing; a later invocation does not discover and recover that backup. On ordinary publish failure, the rollback `file.rename(backup_dir, norm_dest)` return value is ignored. Backup deletion errors are also ignored. These gaps are established by the control flow; no forced process termination was used in this audit.

**Recommendation.** Share the publication state-machine design with the runner, with a cohort-specific ownership validator. Do not call the runner's manifest-specific recovery functions unchanged: merger manifests use a different schema. Record transaction identity, canonical paths, expected fingerprints and phases; recover under the destination lock, verify rollback, and preserve evidence on ambiguity. Check stage directory creation and use collision-resistant stage allocation.

```diff
+recover_cohort_publication(destination, validator=validate_cohort_bundle)
+journal <- prepare_publication(stage, destination, backup, expected_hashes)
 rename(destination, backup)
+persist_phase(journal, 'backup_staged')
 if (!rename(stage, destination)) {
-  rename(backup, destination)
+  restore_verified_backup_or_fail_recovery_required(journal)
 }
+verify_published_bundle(destination, journal)
+persist_phase(journal, 'published')
+checked_cleanup(journal) # never announce clean closure on failed cleanup
```

**Verification criteria.** Kill a child process after each persisted phase and rename; the next invocation recovers one complete old or new bundle. Simulate failed publication, failed restoration and failed cleanup independently. Preserve the only valid copy and identify its path in the error. Verify that malformed journals cannot redirect rename/delete operations outside the transaction's allowed paths.

## H04 — Compare generated cache filenames using filesystem identity

**P2 / Medium.** Locations: `analysis/utils/merge_wf16s_cohort.R:480–486`, `:641–645`, `:681–686`.

The merger rejects a cache basename equal to `config.yml`, `metadata.tsv`, `abundance_table_species.tsv` or `cohort_merge_manifest.json`, but that comparison is case-sensitive. Windows publication is case-insensitive. A valid JSON cache named `CONFIG.YML` passes validation and is copied with `overwrite=TRUE` over the generated configuration.

**Reproduction.** Two valid synthetic Kraken bundles plus an empty JSON cache named `CONFIG.YML` produce a successful `merged` result; published `config.yml` contains **`{}`**. The resulting bundle cannot serve as the intended pipeline configuration. Its manifest can also declare case-colliding output keys.

**Recommendation.** Prefer a fixed generated cache basename. Otherwise validate the complete output-name set with the project's portable case-folded filename contract, and require checked, nonoverwriting copying. Validate the actual staged bundle before publication.

```diff
-if (cache_basename %in% reserved_names) stop(...)
+assert_portable_unique_basenames(c(reserved_names, cache_basename))
-file.copy(taxonomy_cache, out_cache_path, overwrite=TRUE)
+if (!file.copy(taxonomy_cache, out_cache_path, overwrite=FALSE)) stop(...)
+validate_staged_cohort_bundle(stage_dir) # including config paths and census
```

**Verification criteria.** Reject mixed-case variants of every reserved name before creating the destination; check on Windows and POSIX for portable output semantics. Normal JSON cache copying remains byte-identical. Every successful bundle has a parseable full config, distinct artifact paths, and a manifest matching the physical file census.

## H06 — Treat threshold-created empty profiles as undefined Jaccard input

**P2 / Medium.** Locations: `analysis/03_beta_diversity.R:87–112`, `:297–300`; preflight in `analysis/utils/preflight.R:441`.

Nonzero classified depth does not guarantee nonempty presence/absence profiles after `beta.minimum_count`. If two samples have no taxon above the threshold, vegan returns missing Jaccard distances. The module writes those missing values, then classifies the absence of any finite positive distance as “All pairwise distances are zero.” It returns `completed` with no module warnings. In a larger mixed cohort, some positive distances can instead allow later analysis to reach a nonfinite matrix.

**Reproduction.** Two positive-depth samples with taxa counts `(10,20)` and `(20,10)`, `minimum_count=100`, Jaccard only: `distance_jaccard.tsv` has off-diagonal `NA`; PCoA skip text says all distances are zero; module status is completed and warnings are empty. See scratch `jaccard/`.

**Recommendation.** Check occupancy after thresholding, then require all distances to be finite before writing a completed distance product or running downstream inference. Use an explicit undefined-distance diagnostic naming affected samples. Skip only the affected distance analysis where other requested distances remain valid; do not silently remove samples or substitute zero distances.

```diff
+binary_otu <- otu_table >= minimum_count
+if (any(rowSums(binary_otu)==0)) {
+  record_distance_skip('E_EMPTY_THRESHOLD_PROFILE', affected_samples)
+  next
+}
 dist_mat <- vegan::vegdist(binary_otu, method='jaccard', binary=TRUE)
+assert_all_finite_distances(dist_mat)
 # Only a finite distance matrix can enter the all-zero branch.
```

**Verification criteria.** Test all-empty, one-empty, two-empty-plus-nonempty and finite-identical profiles. No missing distance is described as zero. PERMANOVA never consumes a nonfinite matrix. Warnings and skip reasons reach the manifest; requested valid Bray results survive a Jaccard-specific skip.

## H07 — Make resource preflight cover the work that will actually run

**P2 / Medium.** Locations: `analysis/03_beta_diversity.R:58–81`; `analysis/05_ordination.R:55–70`, `:133`; `analysis/utils/preflight.R:441–462`; `analysis/utils/alpha_phylogeny.R:134`; configuration budget keys at `analysis/utils/config.R:174–179`.

Three concrete mismatches undermine the budget contract:

1. Beta's resampling guard uses `n_taxa <- nrow(otu_table)`, although `otu_table` has samples as rows. The check therefore measures samples times iterations and omits the taxa dimension. Its `max_rarefaction_cells` key is not among the explicitly validated budget keys.
2. Distance and permutation checks live inside `run_beta`, not shared preflight. An ordination-only run reaches NMDS distance construction without the distance budget; validate-only does not enforce those beta execution checks.
3. Every phylogenetic alpha calculation invokes `ape::vcv.phylo` on the entire original tree before subsetting to observed taxa. Resampling repeats this allocation. The alpha preflight budgets output rows, not the tree's quadratic covariance allocation. Extra unused tree tips still contribute to that allocation.

These are source/dimension findings. No large allocation was attempted and no specific RAM failure threshold is claimed.

**Recommendation.** Add one pure workload estimator keyed by requested modules, with explicit units and validated limits. Apply it before output mutation and before expensive allocations. Account for sample-by-taxon resampling, actual permutation rows (including exhaustive enumeration), ordination distance work, and phylogenetic covariance dimensions. Cache reusable phylogenetic quantities once, preserving original-root semantics.

```diff
-n_taxa <- nrow(otu_table)
-check(n_taxa * iterations)
+work <- estimate_workload(samples=nrow(otu_table), taxa=ncol(otu_table),
+                          iterations=iterations, tree_tips=length(tree$tip.label),
+                          requested_modules=modules)
+validate_workload(work, cfg$resource_budgets, allow_large_workload)
+# Both validate-only and execution use the same estimator.
-covariance <- ape::vcv.phylo(phylogeny$tree, corr=TRUE) # every metric draw
+covariance <- phylogeny$validated_precomputed_covariance
```

**Verification criteria.** Tiny configured budgets reject beta and ordination-only requests before `vegdist`, `metaMDS`, `shuffleSet` or VCV allocation. Swapping sample/taxon dimensions cannot accidentally preserve the work estimate. Instrument VCV calls to establish at most one intended construction per run, and verify rooted PD/PSR/PSE still match existing oracles. Include a tree with many unused tips without allocating a huge real matrix in the test.

## H08 — Stabilize alpha q evaluation and make metric identities collision-free

**P2 / Medium.** Locations: `analysis/utils/config.R:188–197`; `analysis/utils/metrics.R:50–57`, `:107`, `:122`, `:171–174`, `:214–217`.

Configuration accepts arbitrary distinct finite nonnegative q orders. Direct exponentiation in `log(sum(p^q))/(1-q)` underflows for large q and loses precision near q=1. Separately, formatting q with 15 digits collapses distinct accepted doubles into the same metric key.

**Reproductions.** For `p=c(.5,.5)`, q=2000 returns `Inf`, although the entropy is `log(2)`. At q=`1+1e-15`, it returns `0.7` rather than approximately `0.6931472`. `hill_orders=c(1,1+1e-15)` passes numeric uniqueness but yields duplicate `hill_q1` keys; `calc_alpha_metric_long(c(10,10), ...)` errors with `Unknown alpha metric key 'hill_q1'.`

**Recommendation.** Use log-sum-exp for large-q evaluation and a stable near-one formulation or documented Shannon-limit tolerance. Keep human labels separate from unique machine keys; either use round-trip numeric tokens or reject token collisions during config validation. Do not silently merge requested q orders.

```diff
-log(sum(probabilities^q)) / (1-q)
+if (near_one(q)) stable_shannon_limit(probabilities, q)
+else log_sum_exp(q * log(probabilities)) / (1-q)
-token <- format(q, digits=15, scientific=FALSE)
+token <- round_trip_q_token(q)
+assert_unique_metric_keys(registry) # before running modules
```

**Verification criteria.** Uniform distributions have Renyi entropy `log(S)` and Hill diversity `S` over q=0,1,2,2000 and values on either side of one, within stated tolerances. Skewed distributions remain finite and satisfy expected diversity bounds. Adjacent representable q orders produce unique keys or fail preflight clearly. Default metric names stay backward-compatible.

## H09 — Define the rarefaction boundary for very large accepted counts

**P3 / Low.** Locations: `analysis/utils/io.R:440–453` (safe-integer ingestion), `analysis/utils/metrics.R:256–297` (vegan calls).

Input permits counts far above 32-bit range, and full-depth alpha deliberately retains double storage. The installed pinned-runtime family still has a narrower behavior at the rarefaction boundary: vegan's advisory formats its smallest count with `%d`. Counts `c(3e9,3e9)` therefore fail both analytical rarefaction and resampling, even at requested subsample depth 1000. `suppressWarnings` does not catch a formatting error raised while constructing a warning.

**Reproduction.** Both `calc_analytical_rarefaction(c(3e9,3e9))` and `calc_rarefaction_resamples(c(3e9,3e9),1000,n_iterations=1)` raise `invalid format '%d'; use format %f, %e, %g or %a for numeric objects` with vegan 2.7.3. This is a narrow extreme-count compatibility issue, not a common ONT sample failure. The pipeline already caps configured resampling depth at `.Machine$integer.max`; the finding concerns input cell values, not an unbounded configured depth.

**Recommendation.** Establish a tested numeric contract for each dependency call. Either select and validate a compatible implementation/runtime or explicitly mark rarefaction unavailable beyond its supported domain while preserving valid full-depth metrics. Do not fix this by truncating counts, rescaling them silently, or swallowing arbitrary dependency errors.

```diff
+support <- validate_rarefaction_runtime_domain(counts, requested_depth)
+if (!support$available) {
+  record_rarefaction_skip('E_RAREFACTION_NUMERIC_DOMAIN', support$reason)
+  retain_full_depth_alpha()
+} else {
   curve <- vegan::rarefy(...)
   draws <- vegan::rrarefy(...)
+}
```

**Verification criteria.** Boundary fixtures immediately below/above 32-bit count range either compute against a trusted oracle or yield a precise preflight/skip diagnostic. Full-depth metrics remain available where valid. Small ordinary counts and existing large-count full-depth tests remain unchanged. No count is coerced to `NA` or silently rounded beyond the input contract.

## Implementation sequence and release acceptance

1. **Scientific correctness:** H01 first, then H06 and H08. Add independent numerical oracles before changing algorithms. Identify affected historical statistical outputs for recomputation; hashes alone do not validate their mathematics.
2. **Publication safety:** H02 and H03 as one cohesive transaction change, followed by H04. Separate canonical path identity, bundle ownership validation, journal/recovery state, and artifact construction. Reuse mechanisms across runner/merger without assuming identical manifest schemas.
3. **Provenance and bounded execution:** H05, then H07 and H09. Keep source inventory and release verification independently checkable. Keep workload estimation separate from module execution so validate-only and execution cannot drift.
4. **Release gate:** all existing R/Python/Node suites; every new failure-injection and numerical case above; Windows and Ubuntu CI; full minimap2, Kraken, zero-classified, phylogenetic and FAPROTAX integrations with independent artifact verification. Exercise overwrite with a prior good run and crash recovery with child processes. Only label the candidate release-ready after those gates complete against its exact SHA.

The architectural weaknesses supported by this audit are duplicated publication behavior, repeated producer/verifier inventory omissions, and workload policy split across modules. Address those seams through the findings above rather than a broad rewrite. Existing taxonomy error classification, cache locking/recovery, escaped offline payloads, and classifier reconciliation should retain their current regression coverage.

For every implementation PR, include the finding ID, before/after reproducer, actual verification results, and any platform-specific gate still outstanding. The pseudocode above is deliberately illustrative and is not an applied patch.

## Implementation record (2026-10-11)

Implemented all nine findings in scoped phases. The changes preserve the audit's stated boundaries: new transaction and statistical fixtures use synthetic data, no read sequences were uploaded, no remote taxonomy refresh was made, and this work does not claim to recompute or validate historical biological results.

- **H01 and H06:** PERMANOVA and betadisper now receive the full permutation design; exchangeability is assessed independently of sampled rows. Threshold-created empty Jaccard profiles and non-finite distance matrices produce an explicit skipped-distance diagnostic and warning, while valid requested distances continue.
- **H02, H03, and H04:** cohort replacement now holds a canonical destination lock, journals checked transaction phases, fingerprints the complete prior bundle, validates stage and backup contents at publication boundaries, recovers verified old/new states after process termination, and retains material when state is ambiguous. Portable case-folded artifact checks prevent reserved cache-name collisions. Transaction path names fit conservative Windows path limits.
- **H05:** the embedded Sankey JavaScript client is part of both the producer source digest and independent release-verifier inventory.
- **H07:** shared workload estimates cover beta and ordination distance work, permutation matrices, sample-by-taxon resampling, alpha long-table rows, and original-tree covariance allocation. The same configured budgets run during validate-only preflight and before module output creation. Phylogenetic covariance is computed once per alpha run.
- **H08:** Rényi entropy uses stable near-one and log-sum-exp calculations; round-trip q tokens retain adjacent representable orders and reject any key collision.
- **H09:** vegan rarefaction calls fail with a specific numeric-domain condition beyond its 32-bit count/total boundary. The pipeline records per-sample rarefaction unavailability and keeps valid full-depth alpha metrics.
