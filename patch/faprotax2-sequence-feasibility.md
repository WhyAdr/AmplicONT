# FAPROTAX2 native-Windows sequence feasibility

**Status: P2 sequence mode blocked.** This document records the initial feasibility findings. The final native one-feature trial advanced through MAFFT alignment and APPLES jplace generation, then failed FAPROTAX's reference-tree consistency check before function annotation. See the [final native sequence-trial report](faprotax2-native-sequence-trial.md) for versions, archive hashes, Windows scratch fixes, tree comparison, and resource limits. No production adapter was integrated; P4 remains unimplemented.

## Finding

The sequence interface is real. The initial unmodified one-feature trial loaded one ASV and three sample columns, then exited with status 1: the Windows gzip helper warned about an incomplete final line, MAFFT was not found, and the mapper reported that the ASV could not be aligned. It did not reach placement. In the final isolated native trial, scratch-only fixes let MAFFT and APPLES complete and produce jplace, but FAPROTAX rejected the placement tree because its topology and branch lengths differed from the FAPROTAX reference tree. No function abundance table or report was produced. Sequence mode remains **unverified and blocked**. The local synthetic probe confirms that the decompression target correction works; the native run confirms that tool-launch fixes alone do not clear the sequence-mode gate.

## Evidence and concrete blockers

1. **Windows decompression writes to the gzip input path.** In the official archive's `ensure_uncompressed()` function, the Windows branch calculates `uncompressed_file_path` but opens `file_path` for output (`faprotax.R`, lines 169–181). Sequence mode applies this function to `reference_alignments_sanitized_subset.fasta.gz` before calling MAFFT (around line 1592). I parsed the function AST from the archived source and called it only on a synthetic gzip file under ignored scratch. On native Windows R 4.5.3, the call returned a temporary `.fasta` path that did not exist and changed the synthetic `.gz` input's MD5. An in-memory scratch-only one-argument correction to `file(uncompressed_file_path, "w")` produced the expected uncompressed FASTA while preserving the `.gz` bytes. An earlier disposable mapper trial changed only its run copy; the corresponding file in the unpacked official archive kept its original hash. Final v4 scratch code corrects the output target and preserves the compressed source. The synthetic probe and private pre/post manifests remain in ignored `output/faprotax2-audit/sequence/`. This fix has not been integrated into production.

2. **EPA-NG cannot be the native Windows default.** FAPROTAX defaults to `--placement_program epang` (line 937), while the [official EPA-NG README](https://github.com/pierrebarbera/epa-ng#installation) says Windows is not supported. A native execution must select another supported route.

3. **APPLES 2.0.11 advertises Windows but fails before its Windows branch.** The [APPLES README](https://github.com/balabanmetin/apples) says it supports Windows and documents `pip install apples`; its CLI accepts the mapper's `--ref`, `--tree`, `--query`, `--output`, and `--threads` options and emits jplace output. However, the [official APPLES 2.0.11 entry point](https://github.com/balabanmetin/apples/blob/v2.0.11/run_apples.py) unconditionally calls `mp.set_start_method('fork')` near the start of `main`. It later contains a Windows branch that deliberately processes queries serially. Python 3.12 documents `fork` as POSIX-only and says an unavailable start method raises `ValueError` ([multiprocessing documentation](https://docs.python.org/3.12/library/multiprocessing.html)). The final trial used APPLES 2.0.11 in an isolated native runtime, with a scratch-only guard around the POSIX `fork` call. APPLES' Windows TreeCluster subprocess and representative-sequence setup also needed narrow scratch fixes. The bundled FastTree 2.1.11 ran and produced a jplace file, but FAPROTAX rejected its re-estimated tree. These compatibility changes are not production-integrated; see the [final trial report](faprotax2-native-sequence-trial.md).

4. **The mapper constructs POSIX shell commands for MAFFT and placement.** In `faprotax.R` lines 1595–1597 and 1637–1645, command strings contain single-quoted paths and, for alignment, `>` redirection; both children are started with `system(command)`, and their returned status is ignored. The initial unmodified trial logged `'mafft' not found` and then reported that its input OTU could not be aligned. In the final isolated scratch trial, the official MAFFT v7.526 package was called through `cmd.exe /C` with explicit arguments and completed alignment. The [official MAFFT Windows instructions](https://mafft.cbrc.jp/alignment/software/windows_without_cygwin.html) say its `mafft.bat` must be invoked through `cmd.exe /C` or `call`; the official MAFFT [fragment-addition instructions](https://mafft.cbrc.jp/alignment/software/addsequences.html) document `--auto --addfragments ... --keeplength`. The [R `system` documentation](https://stat.ethz.ch/R-manual/R-devel/library/base/html/system.html) describes Windows shell limitations; R's [`system2()` documentation](https://stat.ethz.ch/R-manual/R-devel/library/base/html/system2.html) covers quoting, redirection, and exit status. The v4 scratch mapper captures status and rejects failed or empty output. Production still needs this integration and focused path testing; no cross-platform path test or test-suite change was made in this investigation.

5. **The current executable checks are not a reliable Windows preflight.** The archived `check_program_exists()` calls `system(program_name)` on Windows, while `check_program_has_argument()` splits an executable-plus-arguments string on spaces and calls `system2()`. These checks do not safely model the batch-file `cmd.exe /C` invocation MAFFT requires, and splitting on spaces breaks executable paths containing spaces. The scratch v4 path uses explicit native invocation data; the production preflight remains unchanged. A production adapter still needs to resolve the executable and invocation separately, validate the actual launch form, and preserve spaces and Unicode in paths.

6. **The mapper may install R packages into whichever library its process sees.** It attempts CRAN installation for `optparse`, `castor` (minimum 1.8.5), and `stringr` when they are absent or outdated. The source uses HTTP CRAN URLs. The scratch native trial set `R_LIBS_USER` to an ignored runtime library; production still needs an explicit dependency preflight and isolated library policy so its auto-installer cannot change the legacy `renv` library.

## Prepared local trial inputs

Controlled trials used disposable copies of the complete official `FAPROTAX_ref_data` under ignored `output/faprotax2-audit/sequence/`. SHA-256 manifests matched copies against the unpacked archive before runs and show that checked original files remained unchanged. Earlier scratch attempts could change only their disposable alignment copy; the final v4 mapper corrected the decompression target and then projected the alignment to the exact tree-tip set. The final tree hash and aggregate comparison are in the [trial report](faprotax2-native-sequence-trial.md).

The final trial used a local one-feature FASTA and matching OTU abundance table from a sample-derived 16S ASV. The feature ID matched exactly; the table had three sample columns and followed the mapper's documented orientation (OTUs as rows and samples as columns). The source table was not changed. The private fixture remains under ignored `output/faprotax2-audit/sequence/` and is not included in the trial report.

## Decision

The final native run completed FASTA-to-alignment-to-jplace for one feature, then exited 1 because APPLES' re-estimated jplace reference tree failed FAPROTAX's consistency check. No functional table or report was written. This is a failed sequence-mode gate, not a partial success. P2 remains blocked until a scientifically valid native path completes annotation end to end with a compatible reference tree. Taxonomy-mode success, an aligned FASTA, or jplace generation alone does not clear this gate. P4 production implementation has not started; see the [final trial report](faprotax2-native-sequence-trial.md) for exact tree evidence and ignored scratch references.
