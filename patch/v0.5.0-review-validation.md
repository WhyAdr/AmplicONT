# Kraken2 implementation review and local validation

Reviewed 2026-10-11 against implementation HEAD `be0762d` (v0.5.0), the refined handoff, the supplied Biomecon/Knegative ITS bundles, and the maintained minimap2 fixtures. Patches remain uncommitted.

## Findings patched

1. **Blocking verifier bug:** the Kraken branch of `tests/verify_release_run.R` used `release_samples` before defining it. Added the missing initialization and Kraken integration to the Ubuntu/Windows CI job. Added explicit `--allow-dirty` development verification; default release verification still requires clean source, and source inventories, locked environments, artifacts, and viewer correspondence remain checked.
2. **Unverified species identity:** the adapter could accept a Bracken TaxID solely because its species name matched one abundance row. It now requires assignment lineage evidence or an exact full-path TaxID cache entry, rejects conflicting assignment lineages, and restricts placeholder equivalence to the corresponding rank. Bracken TaxIDs retain their original character spelling, so leading-zero identifiers cannot be normalized into valid IDs by automatic column conversion.
3. **Incomplete native-report validation:** added tree indentation and per-node clade conservation, root/U identity, rank/name, rounded percentage, and safe-total checks. Bracken validation now checks physical row widths, names, finite bounded fractions, and assigned-plus-added estimate accounting. Fractions need not sum to one or reproduce integer-matrix fractions exactly.
4. **Merger validation and publication gaps:** `--validate-only` previously succeeded without reading assignments or reconciling reports. The merger now applies the pipeline ingestion/accounting contracts before returning success, validates abundance schemas/counts/totals and sample IDs, rejects ambiguous files and silent sample renaming, preserves punctuation in repeated literal `--input` paths, uses actual configured length bounds, rejects missing explicit caches and aggregate overflow, and fingerprints sources before reading and before publication. Case-insensitive overlap checks protect source bundles. Overwrite is restricted to an unchanged merger bundle without unrelated files.
5. **Disconnected provenance:** generated configs now reference `input.cohort_merge_manifest`. Ingestion checks the merged abundance hash, original source hashes, and per-sample mappings. Original abundance tables and the merge manifest are inventoried and guarded against mutation during execution. Metadata and analysis settings remain editable; their generated hashes are historical provenance, not an editing prohibition.
6. **Missing input/output guards and manifest checks:** output-root safety now includes raw Kraken reports, Bracken reports, per-sample params, and merger provenance/source tables. Per-sample params must identify their mapped sample. Revision 5 validates finite scalar settings, safe population counts, supported database/rank, parameter coverage for either classifier, and truthful reconciliation/assignment-availability flags.
7. **Estimate presentation:** alpha/composition figure labels and captions distinguish Bracken species estimates from raw assignment populations. Builtin Krona, explorer, and Sankey HTML explain `E` and `T = E + U`; explorer/Sankey payload metadata and independent correspondence checks retain that basis.
8. **Insufficient fixtures:** cohort tests previously used abbreviated taxonomies and dummy reports. Fixtures now contain consistent producer-shaped assignments and reports. The synthetic Kraken fixture preserves `N=50, C=30, U=20, E=28, T=48, D=2` through two genuine above-species assignments. Added adversarial regression cases for malformed reports, false TaxID matches, count bounds, trailing lineage fields, provenance drift, and overwrite protection.

Native format checks follow the [Kraken2 manual](https://github.com/DerrickWood/kraken2/blob/master/docs/MANUAL.markdown). Bracken's [output writer](https://github.com/jenniferlu717/Bracken/blob/master/src/est_abundance.py) constructs `added_reads` as the integer estimate minus assigned reads; the supplied files satisfy that equality.

## Practical limits and reproduction

- These are local Windows R 4.5.3/Python 3.12 development checks. Ubuntu/Windows CI is configured but has not been run remotely for the uncommitted patches. Clean tagged-release verification remains a separate gate.
- Taxonomy is `cache_only`. The real-data runs start with an empty local cache and retain unresolved/conflicted taxonomy nodes in their provenance: Biomecon 122 unresolved/25 conflicts; Knegative 76/15; cohort 135/25. Counts and species-row reconciliation pass independently of those export-resolution warnings. No NCBI refresh or sequence upload was performed.
- The inherited `C.UTF-8` locale is invalid for this Windows R installation. Final checks use `LC_ALL=English_United States.utf8`; earlier runs showed escaped accented labels and were superseded. R hashing also requires execution outside the desktop sandbox's Windows `file.access` restriction, which rejected files that R could otherwise read. This was an environment limitation, not a bypass of input validation.
- Reproduction scripts, configs, logs, and all five run directories are retained in `output/review-20261011/`. `integrations.py` invokes the pipeline with `--allow-dirty` and invokes `tests/verify_release_run.R OUTPUT --allow-dirty`, retaining exact-source and artifact verification. `final-tests.R` parses all R sources and runs the full testthat suite. `input-audit-final.json` records the post-review full-file input audit.
- At the time of this local review, the original plans and supplied producer outputs were preserved; no commit, push, or remote execution had been performed.

## Publication CI follow-up

The subsequent cleanup and review commit `575f609` triggered
[remote validation](https://github.com/WhyAdr/ont-wf16S-amplicon-postprocess/actions/runs/38098506464).
Both Ubuntu jobs passed. Windows exposed an additional destination-path issue:
`normalizePath(..., mustWork = FALSE)` can retain backslashes and short-name
ancestors when the destination does not exist, defeating lexical overlap checks.
The merger now resolves the existing ancestor before appending missing path
components, both for validation and publication. A regression checks a nested
nonexistent destination with Windows backslashes and short-name input ancestry,
and verifies that rejection creates no directory. The focused local merger suite
passed all 14 cases and 76 expectations with zero failures or errors.
